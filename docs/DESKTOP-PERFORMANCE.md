# v0.4.0-beta.1 Electron 多窗口性能

## 环境与测法

Windows 11 25H2 x64，Electron 45.2.3，Intel Core i7-14650HX，活动 GPU 为 Intel UHD Graphics（驱动 32.0.101.7077）。显示区 1707 × 1067 DIP，Windows 缩放 150%。主窗口客户区固定为 1280 × 720 DIP（约 1920 × 1080 物理像素）。光环只占客户区的一部分。固定画质时，主窗实际 Canvas 约为 1246 × 635 像素，悬浮窗在初始矩阵约为 633 × 531 像素。自动画质的实际像素尺寸随档位变化。两窗播放同一持续活动的 Mock 轮次。

`scripts/desktop-observe.cjs` 在实际 Canvas 调用入口采样。FPS 来自首末绘制提交之间的真实间隔，同时记录 rAF、同步绘制函数耗时、P95、P99 和超过 50 ms 的帧间隔比例。同步绘制耗时只覆盖 JS 和命令提交。每个主要场景轮换顺序采五次，每次采样约 4.5 秒，单独预热。Windows 进程内存查询发生在计时窗之后。Chromium trace 单独采集，并与常规测量分开统计。

双窗各暂停一侧后，另一侧恢复到接近单窗速度。透明窗口在暂停悬浮绘制时仍可见，两个 renderer 仍在。这个对照把开销范围收敛到两路活动绘制及其光栅和合成。

Alpha 的 Chromium trace 在 GPU 进程记录到双窗场景 1148 次 `DoRasterCHROMIUM`，累计 2884.8 ms，其中嵌套的反序列化为 2880.7 ms。`DoEndRasterCHROMIUM` 另有 1145 次，累计 2009.5 ms，其中嵌套 flush 为 1992.8 ms。相同 trace 中 `Display::DrawAndSwap` 累计 46.9 ms，`DXGISwapChainImageBacking::Present` 34.3 ms，`DCompPresenter::Present` 4.4 ms。这些是 Chromium 记录的事件时间，嵌套事件不可相加，内部时间也无法覆盖 DWM、驱动排队或 GPU 硬件执行的全部路径。

主窗单绘的同步 JS 成本接近双窗值。双窗固定画质降帧主要伴随 rAF 回调变稀和共用 GPU 进程的光栅命令处理。后台节流在隐藏及最小化场景生效，双窗掉帧在两个画布可见时复现。Trace 会影响样本，Alpha 双窗固定画质从无 trace 的约 18.1 FPS 到有 trace 的约 17.2 FPS。

试验过强制软件 Canvas context、软件 trail context、软件光栅和将辉光 blur 移到小缓冲区。短测未显示稳定收益，发布版沿用原有 Canvas、硬件路径、光束和辉光。Beta 调整帧预算、低速 rAF 唤醒和长时间隐藏时的缓冲区释放。自动质量判断保留 Alpha 双窗阈值。
